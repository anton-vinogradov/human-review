# Human Review

[English](README.md) | [Русский](README.ru.md)

Human Review помогает подготовить изменения к вашему ревью. Прежде чем передать работу, модель сама перечитывает код и тесты. Она убирает лишние правки, уточняет неясные имена и упрощает код там, где трудно проследить, как он работает.

При чтении легче увидеть, как теперь работает программа и почему модель выбрала такой подход. Вам реже приходится отвлекаться на мелкие замечания. Можно сосредоточиться на самом решении, оценить, верно ли модель поняла задачу, и подсказать ей, что стоит пересмотреть.

Установка зависит от приложения, в котором работает модель. Ниже приведены команды для Codex. У других агентов могут отличаться каталог навыков и способ их вызова.

## Быстрый старт

Если агент поддерживает навыки, доступ к файлам и выполнение команд, отправьте ему этот запрос.

```text
Установи human-review из https://github.com/anton-vinogradov/human-review как навык для текущего агента.
Используй поддерживаемый этим агентом способ установки и каталог навыков.
Если поддерживается установка отдельным Git-клоном, используй её. Автообновление оставь выключенным.
Проверь, что навык доступен. Если установка навыков не поддерживается, сообщи об этом.
```

После установки можно провести ревью в проекте с помощью такого запроса.

> Используй $human-review, чтобы проверить изменения по задаче. Исправь подтверждённые проблемы в её пределах и проверь результат ещё раз.

Если нужны только замечания, укажите это в запросе.

> Используй $human-review для ревью этих изменений. Сообщи замечания без правок в файлах.

В чате без поддержки навыков приложите diff, исходники, нужные для проверки, и русский текст навыка. Затем отправьте запрос ниже. [SKILL.ru.md](SKILL.ru.md)

```text
Проведи ревью приложенного diff по приложенным инструкциям human-review.
Пропусти проверку обновлений для этого вложения. Если human-writing недоступен, следуй правилам письма из приложенного навыка.
```

Это применение инструкций в текущем чате. Такой способ не устанавливает навык и не включает автообновление.

## Что потребуется

- Для ревью по приложенному тексту Git и Python не нужны.
- Для установки командой `git clone` нужен Git.
- Для автообновления нужны Git, Python 3.9 или новее, доступ к сети и право менять установленный навык.
- Все тексты по задаче модель пишет по human-writing. Если навык не установлен, она читает его инструкции в репозитории. Если они недоступны, модель применяет правила письма из Human Review. [human-writing](https://github.com/anton-vinogradov/human-writing)

Полный текст навыка доступен на [английском](SKILL.md) и [русском](SKILL.ru.md). `SKILL.md` — основной файл для установки; `SKILL.ru.md` — его русский перевод. Настройки отображения в Codex находятся в [agents/openai.yaml](agents/openai.yaml).

## Ручная установка в Codex

Для автообновления нужен отдельный клон репозитория. В macOS, Linux, Windows Git Bash и PowerShell подойдёт следующая команда.

```sh
git clone --branch main https://github.com/anton-vinogradov/human-review.git "$HOME/.agents/skills/human-review"
```

Если в каталоге уже есть файлы, Git остановится и сохранит их. Порядок перехода описан ниже. Скопированный навык тоже подходит для ревью, но автообновление требует установки через Git.

## Включение автообновления

По умолчанию автообновление выключено. Чтобы включить его, выполните команду один раз для этой установки.

```sh
python3 "$HOME/.agents/skills/human-review/scripts/update.py" --enable
```

В Windows при необходимости замените `python3` на `py -3`. Если навык установлен в другом месте, укажите путь к нему.

Включение разрешает скачивать и применять будущие коммиты из ветки **main** этого репозитория, включая изменения самого скрипта обновления. Установленную версию определяет хеш коммита. Скрипт меняет только установку навыка. Это не даёт разрешения менять проверяемые проекты.

При использовании навыка агент запускает скрипт перед ревью. Скрипт проверяет обновления не чаще раза в сутки, включая неудачные сетевые попытки. Он применяет только обновления fast-forward: переход к новой версии без объединения разошедшихся историй. После обновления агент перечитывает `SKILL.md` для текущего ревью.

- Локальные правки, изменения в индексе Git, дополнительные файлы, в том числе игнорируемые, и разошедшиеся локальные коммиты сохраняются. Обновление пропускается.
- Другой источник `origin`, ветка, отличная от `main`, или состояние detached HEAD также приводят к пропуску обновления.
- Отсутствие инструментов, сети или разрешений и превышение времени ожидания не блокируют ревью. Установленные инструкции остаются доступны. Таймаут одной операции Git — 15 секунд.
- Проверка выполняется при использовании навыка. Фонового процесса нет; запуск зависит от агента и разрешений среды.

Чтобы проверить обновления сразу, пропустив только проверку суточного интервала:

```sh
python3 "$HOME/.agents/skills/human-review/scripts/update.py" --force
```

Чтобы выключить автообновление:

```sh
python3 "$HOME/.agents/skills/human-review/scripts/update.py" --disable
```

Настройка, время последней попытки и блокировка обновления хранятся в каталоге `.git` установки. `--force` не отменяет настройку пользователя и защиту локальных изменений. Скрипт печатает результат в JSON: `enabled`, `disabled`, `current`, `updated` или `skipped`. По результату можно проверить, сохранилась ли настройка. Ошибка обновления не означает, что ревью нужно остановить.

## Переход с существующей установки

Изменение репозитория на GitHub само по себе не добавит скрипт обновления в старые копии.

- **Чистый клон Git без локальных коммитов:** обновите рабочую копию ветки `main` командой `git pull --ff-only` из этого репозитория.
- **Скопированные файлы, установка через skill-installer или клон Git с локальными правками или коммитами:** перенесите старый каталог навыка в резервное место вне каталогов обнаружения навыков. Создайте клон на прежнем месте. Сохраняйте резервную копию, пока не проверите личные правки. Если вернуть эти правки в установленный навык, автообновление будет пропускаться.

Чтобы включить автообновление после перехода, один раз выполните `--enable` для новой установки. Оставьте в каталогах навыков одну установку `human-review`, чтобы агент не выбрал старую копию. Сброс изменений, автоматическое объединение локальных правок и удаление существующей установки не требуются.

## Разработка

По критериям ревью можно проверить, как меняется поведение модели при правке навыка. Правила формирования описывают, как писать навык и проверять его установку и обновление. [Критерии ревью](docs/criteria.ru.md) · [Правила формирования навыка](docs/authoring.ru.md)

Запуск тестов скрипта обновления без доступа к сети:

```sh
python3 -B -m unittest discover -s tests -v
```
