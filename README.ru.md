# Human Review

[English](README.md) | [Русский](README.ru.md)

Инструкции для ревью кода: проверка необходимости каждой правки, сохранения требуемого поведения и возможности использовать более простое решение.

Установка зависит от приложения, в котором работает модель. Ниже приведены команды для Codex. У других агентов могут отличаться каталог навыков и способ их вызова.

## Быстрый старт

Если агент поддерживает навыки, доступ к файлам и выполнение команд, скопируй в него этот запрос:

```text
Установи human-review из https://github.com/anton-vinogradov/human-review как навык для текущего агента.
Используй поддерживаемый этим агентом способ установки и каталог навыков.
Если поддерживается установка отдельным Git-клоном, используй её. Автообновление оставь выключенным.
Проверь, что навык доступен. Если установка навыков не поддерживается, сообщи об этом.
```

После установки в Codex можно отправить такой запрос:

> Используй $human-review для ревью этого diff. Объясни необходимость добавлений, проверь предположения о жизненном цикле объектов и найди подходящие существующие механизмы. Не меняй код.

Для чата без поддержки навыков прикрепи [SKILL.ru.md](SKILL.ru.md), diff и исходники, нужные для понимания изменений. Затем отправь:

```text
Проведи ревью приложенного diff по приложенным инструкциям human-review.
Пропусти раздел об автообновлении. Если human-writing недоступен, используй правила письма из раздела 7.
```

Это применение инструкций в текущем чате. Такой способ не устанавливает навык и не включает автообновление.

## Что потребуется

- Для ревью по приложенному тексту Git и Python не нужны.
- Для установки командой `git clone` нужен Git.
- Для автообновления нужны Git, Python 3.9 или новее, доступ к сети и право менять установленный навык.
- Для документации и пояснений используется [human-writing](https://github.com/anton-vinogradov/human-writing). Если он не установлен, агент читает его инструкции из репозитория. Если они недоступны, в разделе 7 human-review есть основные правила письма.

Полный текст навыка доступен на [английском](SKILL.md) и [русском](SKILL.ru.md). `SKILL.md` — основной файл для установки; `SKILL.ru.md` — его русский перевод. Настройки отображения в Codex находятся в [agents/openai.yaml](agents/openai.yaml).

## Ручная установка в Codex

Чтобы установка поддерживала автообновление, создай отдельный клон Git-репозитория. Команда для macOS, Linux, Windows Git Bash и PowerShell:

```sh
git clone --branch main https://github.com/anton-vinogradov/human-review.git "$HOME/.agents/skills/human-review"
```

Если каталог уже существует, Git остановится и не перезапишет его. Порядок перехода описан ниже. Скопированный навык тоже подходит для ревью, но автообновление требует установки через Git.

## Включение автообновления

Автообновление выключено, пока ты явно не включишь его для этой установки:

```sh
python3 "$HOME/.agents/skills/human-review/scripts/update.py" --enable
```

На Windows при необходимости замени `python3` на `py -3`. Если навык установлен в другом месте, используй этот путь в командах.

Включение разрешает скачивать и применять будущие коммиты из ветки **main** этого репозитория, включая изменения самого скрипта обновления. Установленную версию определяет хеш коммита. Скрипт меняет только установку навыка. Это не даёт разрешения менять проверяемые проекты.

При использовании навыка агент запускает скрипт перед ревью. Скрипт проверяет обновления не чаще раза в сутки, включая неудачные сетевые попытки. Он применяет только обновления fast-forward: переход к новой версии без объединения разошедшихся историй. После обновления агент перечитывает `SKILL.md` для текущего ревью.

- Локальные правки, изменения в индексе Git, дополнительные файлы, в том числе игнорируемые, и разошедшиеся локальные коммиты сохраняются. Обновление пропускается.
- Другой источник `origin`, ветка, отличная от `main`, или состояние detached HEAD также приводят к пропуску обновления.
- Отсутствие инструментов, сети или разрешений и превышение времени ожидания не блокируют ревью. Установленные инструкции остаются доступны. Таймаут одной операции Git — 15 секунд.
- Проверка выполняется при использовании навыка. Фонового процесса нет; запуск зависит от агента и разрешений среды.

Чтобы проверить обновления сразу, пропустив только проверку суточного интервала:

```sh
python3 "$HOME/.agents/skills/human-review/scripts/update.py" --force
```

Чтобы выключить автообновление:

```sh
python3 "$HOME/.agents/skills/human-review/scripts/update.py" --disable
```

Настройка, время последней попытки и блокировка обновления хранятся в каталоге `.git` установки. `--force` не отменяет настройку пользователя и защиту локальных изменений. Скрипт печатает результат в JSON: `enabled`, `disabled`, `current`, `updated` или `skipped`. Проверяй этот результат, чтобы убедиться, что настройка сохранена. Ошибка обновления не означает, что ревью нужно остановить.

## Переход с существующей установки

Изменение репозитория на GitHub само по себе не добавит скрипт обновления в старые копии.

- **Чистый клон Git без локальных коммитов:** обнови рабочую копию ветки `main` командой `git pull --ff-only` из этого репозитория. Один раз выполни команду `--enable`, указанную выше.
- **Скопированные файлы, установка через skill-installer или клон Git с локальными правками или коммитами:** перенеси старый каталог навыка в резервное место вне каталогов обнаружения навыков. Создай клон на прежнем месте и выполни `--enable`. Сохраняй резервную копию, пока не проверишь личные правки. Если вернуть эти правки в установленный навык, автообновление будет пропускаться.

Оставь одну доступную для обнаружения установку `human-review`, чтобы агент не выбрал старую копию. Сброс изменений, автоматическое объединение локальных правок и удаление существующей установки не требуются.

## Разработка

Запуск тестов скрипта обновления без доступа к сети:

```sh
python3 -B -m unittest discover -s tests -v
```
